## 0. 우선순위 원칙

1. **사용자 가시성 (UX)** — 화면에 보이는 것 우선.
2. **데이터 무결성** — schema/migration 은 위험할수록 빨리 처리.
3. **부채 청산** — 절반만 끝난 인프라 (handler, _extra) 마무리.

하도록 file ownership 충돌 분석 포함.

### v1.8.0 — _extra namespace usage audit
**WHY:** v1.4.4-v1.4.6 에서 도입된 `_extra.{workspace|terminal|browser|plan|permission}`
는 schema-less JSON 으로 시작. 일부 필드는 자주 query 됨 (column 으로
promote 필요), 일부는 array 라 JSON 유지가 적합. 어떤 필드가 어떻게
쓰이는지 audit 후 promote 결정.

**범위:**
- `_extra` 모든 caller grep + frequency count.
- 각 namespace 별 schema 추론 (TypeScript type 또는 zod).
- 결과 → `docs/extra-namespace-audit.md` (read-only deliverable).
- 코드 변경 X — 다음 슬롯의 input.

### v1.8.1 — _extra columns promote
**WHY:** v1.8.0 의 audit 결과 기준 자주 query 되는 scalar 필드를
column 으로 promote. JSON 추출 cost 제거 + 인덱스 가능.

**범위:**
- Migration N+1 — 각 promote 대상 column ADD.
- Backfill: 기존 row 의 `_extra.X` → column 복사.
- Read 측: `_extra.X` 우선 column → fallback `_extra.X`.
- Write 측: column 직접.
- 다음 batch 에서 _extra.X 삭제 (v1.8.2 또는 v1.9.x).

### v1.8.2 — _extra schema 문서화 + contract test
**WHY:** v1.8.1 후에도 `_extra` 는 array/object 필드용 합법. 어떤
필드가 어디 사는지 명확한 문서 + 새 PR 에서 `_extra.X` 추가 시
test 가 schema 등록 강제.

→ **결과**: `MetadataExtraSchema` (strict zod) 등록. lint rule 대신
`tests/storage/extraSchemaContract.test.ts` 가 미등록 필드를
자동 차단. canonical 문서: `docs/extra-namespace-schema.md`.

### v1.8.3 — dual-write read 제거
**WHY:** v1.8.1 의 transition 구간 마무리. `assembleSession` 의 `_extra`
fallback 제거 → column 만 source of truth. `buildStoredMetadata` 는
한 슬롯 더 dual-write 유지 (v1.8.4 에서 stop write 예정).
