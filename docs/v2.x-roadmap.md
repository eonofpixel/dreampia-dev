# Dreampia-Dev v2.x Roadmap

> **상태**: 2026-05-08 작성. baseline = package.json v1.8.5.
> 이전 [v1.x-roadmap.md](v1.x-roadmap.md) 는 v1.0.6 시점 audit 으로 stale (~95% land).
> 본 문서는 코드 현실 기준 차기 phase 정의.
> 어떤 sub-deliverable 이 어디서 land 됐는지 → [v1.x-completion-audit.md](v1.x-completion-audit.md).

---

## 진행 원칙

1. **Inventory-first**: 새 phase 진입 전 architect/explore 로 stale 여부 확인 (v1.1.5/6/7 모두 stale 패턴 반복).
2. **Score-driven**: 항목 결정 시 (Risk × Value) / Effort 점수화 후 우선순위.
3. **Verification-before-completion**: 각 deliverable 종결 시 architect verify + evidence (test/build).
4. **Single-PR breaking**: API breaking change 는 분리된 phase 로 묶어 semver clarity 확보.

## Phase A — Hotfix Sweep → v1.9.0

**Goal**: v1.x 의 마지막 잔존 부채 청산. 보안/audit/type 무결성 회복.
**Effort**: 5-7일
**Prerequisite**: 없음
**Ship**: v1.9.0

### Deliverable

| ID | 항목 | Effort | 권고 순서 |
|----|------|:---:|:---:|
| A1 | **L1 respond audit log** — `permission/respond` IPC 핸들러에서 `AuditLogStore` 에 `permission.granted/denied` event emit | 0.5일 | 1 |
| A2 | **F3/H2 PermissionRequest discriminator** — zod discriminated union + 11 파일 type narrow 통일 | 1일 | 2 |
| A3 | **drive16-4 timeout** — `CliProviderOptions.timeout_ms` 추가 + ADR + e2e | 1-2일 | 3 |
| A4 | **VCR production gate** — `auto.ts` 외 production CliProvider entry 에 `shouldRequireFixture` 검증 + startup log + e2e gate | 1일 | 4 |
| A5 | **MetadataExtra legacy optional 결정** — `plan.active`, `permission.default_level` 두 필드 strict removal vs 유지 ADR | 0.5-1일 | 5 |

### 종결 조건
- A1~A4 모두 e2e/vitest pass
- A5 결정문 commit
- Architect verify
- v1.9.0 tag

## Phase B — Plugin 격리 + 보안 강화 → v2.0.0

**Goal**: Plugin 의 untrusted RCE 격리. trust-on-install (D1) 의 다음 단계.
**Effort**: 1.5-2주
**Prerequisite**: Phase A (audit pipe + type narrowing)
**Ship**: v2.0.0 (major bump — Plugin API breaking change)

### Deliverable

| ID | 항목 | Effort | 비고 |
|----|------|:---:|------|
| B1 | **격리 mechanism ADR** — utility_process vs worker_threads vs sandbox VM | 1일 | DX 영향 큰 결정 |
| B2 | **utility_process / worker_threads PoC** | 3-4일 | ADR 결정에 따름 |
| B3 | **Capability gate runtime 강제** — 현재 manifest 검토만, runtime 시점에도 cap 검증 | 1-2일 | F4 audit 에서 명시된 gap |
| B4 | **Plugin sandbox e2e regression spec** | 1일 | RCE 차단 검증 |
| B5 | **Signed manifest 검증 (옵션)** — 사용자 결정. signature verification 채택 여부 | 1-2일 | 채택 시 PKI overhead |

### 종결 조건
- B2 PoC 가 기존 PluginHookRunner 와 backward-compat (opt-in flag)
- B3 e2e 가 capability 미승인 plugin 의 runtime 차단 검증
- ADR commit
- semver = v2.0.0 (breaking)
